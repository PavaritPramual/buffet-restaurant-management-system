## แนวทางภาพ

ก่อนวางจริงต้องตรวจ template ใน Canva ใช้รูปแบบเดิมของชุดนั้น หากยังไม่มีรูปแบบ ให้ใช้ Noto Sans Thai, primary `#9A3412`, background `#FFFDF9` ตามทีม หนึ่งประเด็นต่อหน้า ใช้ diagram กับคำสั้น ๆ และย้ายคำอธิบายไป speaker notes ไม่วางรายงาน audit หรือ logs ยาวบนสไลด์

## หน้า 1 — งานของปวริศช์

### ข้อความบนสไลด์

**โต๊ะและรอบการรับประทานอาหาร**

โต๊ะ • แพ็กเกจ • น้ำซุป • DiningSession

เปิดโต๊ะ → QR → ขอคิดบิล → ปิดรอบ

### ภาพที่ใช้

เส้นทางสั้น ๆ แสดงจุดที่โมดูล Session เชื่อม Ordering และ Billing/Payment

### คำพูดประกอบ

ผมดูแลข้อมูลโต๊ะ แพ็กเกจ น้ำซุป และรอบกิน รวมถึงจุดเชื่อมให้ Ordering และ Billing อ่านข้อมูลรอบจริง แต่ละโมดูลยังมีเจ้าของของตัวเอง งาน integration ทำให้ข้อมูลเดียวกันไหลตั้งแต่เปิดโต๊ะจนปิดรอบได้

## หน้า 2 — สถาปัตยกรรมระบบ

### ข้อความบนสไลด์

React → Controller → Service → Repository → PostgreSQL

Controller รับคำขอ

Service ตรวจเงื่อนไขและ transaction

Repository อ่านและบันทึกข้อมูล

### ภาพที่ใช้

[Component Diagram](../diagrams/previews/component.svg) เป็นแหล่งอ้างอิง เลือกส่วน layers กับ modules ที่ต้องพูดเพื่อให้อ่านได้บนจอ

### คำพูดประกอบ

หน้าเว็บส่งคำขอมายัง Controller ซึ่งเรียก Service เพื่อทำกฎธุรกิจ Service ใช้ Repository ติดต่อฐานข้อมูล ส่วน interface ที่เชื่อมโมดูลช่วยให้ Ordering และ Payment ทำงานกับข้อมูลที่ต้องใช้โดยไม่ส่ง Entity ข้ามกันทั้งก้อน

## หน้า 3 — เปิดโต๊ะและสร้างรอบกิน

### ข้อความบนสไลด์

โต๊ะว่าง + จำนวนคน + แพ็กเกจ + น้ำซุป

ล็อกโต๊ะ → ตรวจข้อมูล → เก็บราคา ณ ตอนเปิด → สร้างรอบ

Session: ACTIVE · Table: OCCUPIED

### ภาพที่ใช้

[Open Session sequence](../diagrams/previews/sequence-open-session.svg) เป็นแหล่งอ้างอิง ย่อเป็น flow ที่อ่านง่าย

### คำพูดประกอบ

การเปิดโต๊ะกับสร้างรอบอยู่ใน transaction เดียวกัน ล็อกแถวโต๊ะเพื่อกันพนักงานสองคนเปิดโต๊ะเดียวกันพร้อมกัน ตรวจจำนวนคนกับความจุ และรับแพ็กเกจกับน้ำซุปที่ยังใช้งานได้ ราคาแพ็กเกจถูกเก็บเป็น snapshot เพื่อใช้คิดบิลของรอบนั้น

## หน้า 4 — QR และสิทธิ์ลูกค้า

### ข้อความบนสไลด์

สแกน QR → แลกสิทธิ์ครั้งเดียว → รับ HttpOnly cookie

หมุน QR ใหม่หลังแลกสำเร็จ

ตรวจสิทธิ์และรอบ ACTIVE ทุกคำขอ

### ภาพที่ใช้

[QR exchange sequence](../diagrams/previews/sequence-qr-exchange.svg) เป็นแหล่งอ้างอิง แสดงมือถือ เว็บ และ backend โดยไม่ใส่ token หรือ cookie จริง

### คำพูดประกอบ

รหัส QR อยู่ใน fragment แล้วหน้าเว็บล้างออกและส่งผ่าน body เพื่อแลกสิทธิ์ Backend หมุนรหัส QR ใหม่และออก cookie ต่อเครื่อง เก็บเฉพาะ hash ของ credential ในฐานข้อมูล มือถือเครื่องถัดไปใช้ QR รุ่นถัดไปได้ และเมื่อปิดรอบสิทธิ์ลูกค้าจะใช้ต่อไม่ได้

## หน้า 5 — จุดเชื่อมและ SOLID

### ข้อความบนสไลด์

SessionContextProvider → Ordering

DiningSessionBillingReader → Billing

PaymentStatusLookup → ตรวจผลชำระก่อน close

แยกข้อมูลตามหน้าที่ • เชื่อมผ่าน interface

### ภาพที่ใช้

Interface 3 จุดกับโมดูลที่เรียกใช้ อ้าง [SOLID analysis](../solid-analysis.md) และ [Session class diagram](../diagrams/previews/class-table-session.svg)

### คำพูดประกอบ

แต่ละโมดูลอ่านเฉพาะข้อมูลที่จำเป็นผ่าน interface เช่น Ordering อ่านรอบและแพ็กเกจ Billing อ่านราคา snapshot และจำนวนคน ส่วน Session ตรวจผล Payment ของรอบเดียวกันก่อนปิด จุดเหล่านี้แสดงการแยกหน้าที่และการพึ่ง contract ที่เล็ก ไม่ได้หมายความว่าทุกจุดในระบบผ่าน SOLID แล้ว ข้อขาดจาก audit ต้องแก้และ review ก่อนรับรอง Final

## หน้า 6 — ขอคิดบิล ชำระ และปิดโต๊ะ

### ข้อความบนสไลด์

ขอคิดบิล → หยุดออเดอร์ใหม่ → รับชำระ → PAID → พนักงานปิดรอบ

Session: COMPLETED · Table: AVAILABLE

ยอดจาก backend · ราคาตอนเปิดรอบ · ตรวจ PAID ของรอบเดียวกัน

### ภาพที่ใช้

[Billing/Payment sequence](../diagrams/previews/sequence-billing-payment.svg) เป็นแหล่งอ้างอิง แสดง PAID และ close เป็นคนละขั้น

### คำพูดประกอบ

เมื่อลูกค้าขอคิดบิลทุกมือถือในรอบนั้นสั่งเพิ่มไม่ได้ แต่ยังดูข้อมูลได้ Backend คำนวณยอดจากราคา snapshot และจำนวนคน หลังรับชำระแล้วพนักงานต้องกดปิดรอบแยก Session ตรวจ PAID ของรอบเดียวกันอีกครั้งก่อนคืนโต๊ะว่าง Order กับ bill request และ close ใช้ session lock ร่วมกันเพื่อให้คำขอที่ชนกันมีลำดับแน่นอน

## หน้าสรุป tests ของทีม — ข้อเสนอเพิ่มเติม

ให้ศิระพัทธ์เป็นเจ้าของหน้านี้ ใช้เพียงข้อความสรุปและหลักฐานอ่านได้:

- เปิดโต๊ะซ้ำและคำขอพร้อมกัน: ไม่เกิดสอง active sessions
- QR ใช้ซ้ำหรือสิทธิ์ผิดรอบ: เข้าถึงไม่ได้
- ขอคิดบิลแล้ว: ไม่มีออเดอร์ใหม่
- ปิดก่อนชำระ: ถูกปฏิเสธ; หลัง PAID ยังต้อง close แยก

เลือกเฉพาะกรณีที่มีผลตรวจของรุ่นส่งจริง ใส่ commit/environment และลิงก์ Test Report อย่าอ้าง CI/local tests ว่าเป็น public browser acceptance หากยังไม่ได้ตรวจ ไม่ต้องอ่าน test case หรือ logs ทุกอันระหว่างพรีเซนต์
